# Forge · AI 创作与交付工作台

## 项目简介

Forge 面向“从想法到可用产物”的创作与交付过程，目标是在同一个工作台中完成需求表达、任务执行、产物预览、验证、交付和持续修改。

**当前版本以网页应用创作为首条已实现的工作流。** 未来可扩展文档总结、文档生成、视频生成等能力。

工作台的能力标准：

| 阶段 | 能力要求 | 当前覆盖情况 |
| --- | --- | --- |
| 输入 | 理解目标、素材和约束，必要时向用户澄清 | 支持文本需求与需求记忆；尚无通用素材上传 |
| 编排 | 按任务类型执行步骤，记录状态，支持确认与恢复 | 已实现网页开发的固定工作流和条件分支；尚无跨类型工作流注册机制 |
| 创作 | 调用适合的模型和工具产出内容 | 已实现网页代码与网页设计图生成；尚无文档、视频生成 |
| 预览 | 在工作台中查看和操作产物 | 已实现代码、设计图和可运行网页预览 |
| 验证 | 按产物类型检查质量，给出证据和修复依据 | 已实现网页运行、有限交互和视觉差异检查 |
| 交付 | 保存版本，提供可用的下载或访问方式 | 已实现 HTML 下载和只读预览链接；尚无生成应用独立部署 |
| 迭代 | 根据反馈持续修改，保留项目目标与约束 | 已实现项目需求记忆、版本快照和多轮修改上下文 |

当前网页创作流程：

```text
输入需求 → 需求梳理 → 设计图生成与确认 → 代码开发 → 验证与有限修复 → 预览与交付
                                                                           ↓
                                               项目记忆与当前代码 → 下一轮修改
```

技术栈：React、TypeScript、Vite、FastAPI、LangGraph、SQLite、Playwright，以及通过 SSH stdio 连接的 UIProof MCP。代码生成接入 DeepSeek；需求梳理、设计规格、视觉理解和图像生成使用阿里云百炼。

| 演示与部署 | 固定待办演示、本地运行、Docker Compose，以及 yun2 上的应用和隔离 Worker 部署 | 域名与 HTTPS、自动发布回滚、运行监控 |

当前边界：

- 多页应用使用 Hash 路由。浏览器按页面与状态检查和截图，UIProof 目前只对有基准图的首页做像素比较。
- 不可修改项目前作为模型上下文约束，仍需测试和人工检查，不能视为强制的代码修改权限控制。
- 30% 指 UIProof 的像素差异比例，不等同于功能未完成比例；截图不能证明业务功能正确。
- 恢复历史代码不回滚业务数据或需求记忆。
- 预览链接对应指定代码快照，持有者可访问；当前本机地址适用于同一电脑的其他浏览器，跨设备访问需要后续部署。
- UIProof 已接入现有远端服务；这不代表 Forge 本身已部署到云端。已在 yun2 完成镜像构建并启动 Forge 后端和 Worker；现有 UIProof 容器保持独立。

### 共享平台能力扩展

这些基础能力用于支撑多种创作任务，不能仅通过新增提示词完成：

- **能力与工作流注册**：根据任务类型选择流程，为各专项节点定义输入、输出、工具权限和失败处理。
- **统一产物管理**：区分代码、图片、文档、视频和音频，记录来源与版本，提供对应的预览、下载和存储生命周期。
- **持久任务执行**：引入后台任务队列、执行器调度、并发控制、超时预算和断线恢复，支撑耗时较长的视频等任务。
- **模型服务适配**：配置不同供应商及用途，记录调用费用、耗时和错误；将文本、图像、视频接口差异封装在适配层。
- **分类验证**：网页检查交互与视觉，文档检查来源和排版，视频检查生成状态、时长及内容；UIProof 继续负责网页视觉验证。
- **交付与集成**：增加独立发布、GitHub 同步、外部资料连接、团队共享及访问权限管理。

建议先完善已有网页工作流与需求记忆，再加入文档总结和文档生成，最后扩展视频、演示文稿等对后台任务和媒体存储要求更高的能力。

## 项目配置

### 环境要求

- Python 3.11+、uv。
- Node.js 22+、npm。
- Git；UIProof 连接还需要 SSH 客户端。
- Playwright Chromium 浏览器。
- 可选：Docker 与 Docker Compose。

在项目根目录创建配置文件：

```bash
cp .env.example .env
```

编辑 `.env`：

```dotenv
# 代码生成：DeepSeek 官方 API
DEEPSEEK_API_KEY=替换为你的DeepSeekAPI密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
CODE_MODEL=deepseek-flash

# 需求、设计及视觉模型：使用百炼 API Key，不是 RAM AccessKey
DASHSCOPE_API_KEY=替换为你的百炼API密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com
TEXT_MODEL=qwen3.7-plus
VISION_MODEL=qwen3.7-plus
IMAGE_MODEL=qwen-image-3.0

# 本地服务
RUNNER_URL=http://127.0.0.1:8011
APP_ORIGIN=http://127.0.0.1:5173
DATA_DIR=./data

# 视觉验收
VISUAL_VALIDATOR=uiproof
UIPROOF_SSH_HOST=yun2
UIPROOF_REMOTE_COMMAND=/opt/uiproof/bin/mcp
UIPROOF_TUNNEL_PORT=49317
UIPROOF_TIMEOUT=180
```

配置说明：

- 代码开发的静态布局、交互实现和修复使用 DeepSeek，独立读取 `DEEPSEEK_API_KEY`。带设计图生成默认使用支持图片输入的 `deepseek-flash`，参考 [DeepSeek 官方视觉文档](https://api-docs.deepseek.com/guides/vision/)。`DEEPSEEK_BASE_URL` 可设为官方根地址或 `/v1` 地址，不追加 `/chat/completions`。
- `TEXT_MODEL` 控制需求梳理与设计规格，`VISION_MODEL` 控制截图理解，`IMAGE_MODEL` 控制生图；这些能力继续使用百炼密钥。

- 百炼密钥必须与接口地域匹配，并开通所选模型。上述地址对应北京地域。需求、视觉理解和图像接口共用该基础域名，请勿在 `DASHSCOPE_BASE_URL` 后追加 API 路径。
- `VISUAL_VALIDATOR=uiproof` 使用 UIProof；设为 `model` 可使用原有模型视觉判断。密钥未配置时可选择演示模式。
- UIProof 需要当前运行环境能够免密执行 `ssh yun2`，且已配置主机指纹。远端入口必须存在。无需修改本机全局 MCP 配置。
- 临时隧道只提供本次待验收页面，任务结束后关闭。基准图片和验收证据会保存在 UIProof 服务器。
- `APP_ORIGIN` 应与前端开发访问地址一致，`localhost` 和 `127.0.0.1` 不同。
- `.env` 不提交到仓库。修改配置后需重启后端。
- 历史代码恢复不回滚业务数据或项目需求记忆；浏览器存储也不会自动迁移到其他浏览器。

## 启动方式

以下命令均从项目根目录执行。

### 首次安装

```bash
uv sync
npm --prefix forge ci
uv run playwright install chromium
```

Linux 环境如缺少浏览器系统依赖，可使用：

```bash
uv run playwright install --with-deps chromium
```

### 本地启动

构建前端：

```bash
npm --prefix forge run build
```

终端一启动浏览器 Worker：

```bash
uv run uvicorn runner.main:app --host 127.0.0.1 --port 8011
```

终端二启动工作台后端：

```bash
uv run uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

打开 [http://127.0.0.1:8010](http://127.0.0.1:8010)。后端会托管已构建的前端文件，无需另启前端服务。

完成首次安装后，也可以使用以下脚本安装项目依赖、构建前端并同时启动两个服务：

```bash
./scripts/dev.sh
```

启动前请停止已有的 8010、8011 服务，避免端口占用。脚本不负责下载 Playwright 浏览器，需先完成首次安装。

### 前端开发

保持上述两个服务运行，再启动 Vite：

```bash
npm --prefix forge run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。Vite 将 `/api` 请求代理至本地后端。

### 容器启动

项目提供 Docker Compose 配置，可在具备相应环境的机器上运行：

```bash
APP_ORIGIN=http://localhost:8010 docker compose up --build -d
```

打开 [http://localhost:8010](http://localhost:8010)。项目数据保存于 `forge-data` 卷，浏览器 Worker 不公开端口。

容器内的 UIProof SSH 别名、主机指纹及授权方式需要单独配置，不会自动继承宿主机设置。部署时将 `APP_ORIGIN` 改为实际访问来源。yun2 已完成程序部署，TCP 80 已放行并通过公网访问验证。


### yun2 部署

- 服务器入口：`http://120.53.16.86/`（TCP 80 已放行，公网访问已验证）。
- 发布目录：`/opt/forge/current` 指向当前发布目录；服务通过 Docker 重启策略自动恢复。
- 云端 `.env`：`/opt/forge/.env`，权限 `600`，独立复制，不提交 Git。
- 持久数据：`/opt/forge/data`；本地项目数据没有自动迁移到云端。
- 服务：`forge-app-1`（80 → 8010）、`forge-runner-1`（内部网络，无公网端口）。
- 部署配置：`deploy/compose.yun2.yaml`；部署专用镜像使用已验证的前端构建产物，浏览器 Worker 复用服务器已有 `uiproof:20261101` 镜像环境，不更改现有 UIProof 容器。
- UIProof：专用受限账号只可执行 `/opt/uiproof/bin/mcp`，只允许 `127.0.0.1:49318` 回环转发。应用不持有本机 SSH 私钥，也不挂载 Docker 管理 socket。`deploy/prepare-uiproof.sh` 涉及账号与 sudo 授权，首次配置须经管理员明确批准。

服务器上管理服务：

```bash
cd /opt/forge/current
docker compose -f deploy/compose.yun2.yaml ps
docker compose -f deploy/compose.yun2.yaml logs --tail 100 app
docker compose -f deploy/compose.yun2.yaml restart app
```

已验证云端模型最小调用返回 200、Worker 交互与截图、UIProof 连接和像素比较、演示任务交付、需求记忆保存及无工作台登录态的预览链接访问。UIProof 示例不匹配设计图时正确返回不通过。当前没有配置域名与 HTTPS。

### 设计与代码一致性

新建项目先生成并校验结构化设计规格，固定设计视口、字号、配色、模块顺序、桌面列宽和移动端断点。生图与代码共用同一规格，限制设计图增加需求外内容或无法实现的复杂素材。首次开发分为静态布局还原和交互实现两个阶段，代码中保留模块标记，系统附加布局约束样式；浏览器检查模块缺失、顺序和列数，差异反馈限定局部修复范围。

工作台按设计图的原始视口运行网页，再整体缩放至面板，避免图片缩小展示、网页却按窄面板重新排版造成的误判。游戏生成提示要求在 `forge_capture=1` 时保持未开始、分数0和固定初始位置；Worker 与 UIProof 均使用该参数。复杂素材尚未实现自动拆分与复用，生成模型也不能保证像素级一致；已有项目不会自动改写代码，可在下一轮修改时从原图提取设计规格。

当连续三次生成后差异仍大于 30%，或功能验证仍未通过，转到交付预览并标记任务完成，结果提示“当前生成暂未满足您的要求，请联系开发人员处理。”；差异不超过 30% 且交互通过时仍由用户选择保留或重新生成。

自动修复和用户主动重新生成共用每个任务三次生成的总次数，不因用户选择重新生成而清零。第三次不再等待确认，直接展示最后生成版本；原始验证结果仍保留，未通过项不会计入已验收的项目需求记忆。

修改任务先合并本轮与历史需求，再生成代码；截图使用固定状态，交互检查进入正常运行状态。单步撤销的验收应覆盖精确分数、禁用、连续点击、刷新与无效操作，不以按钮文字存在作为功能通过依据。


## 视觉结构与多页交付

- 选择开发前生成设计图后，Forge 使用现有视觉模型提取模块内关键元素、文字、初始可见性和归一化估计边界，经设计结构校验后与原图一同传给代码模型。设计标签可展开 JSON。结构提取不需要额外 MCP 服务。
- 在需求中明确首页、列表、详情和设置等页面。Forge 为各声明路由至少安排一次直接进入检查，模型可为交互状态补充操作与断言，最多八条路由、十二个用例。预览可按页面和状态查看截图，失败证据进入下一轮修复。
- 在预览中点击「选取组件」，再点击目标并提交修改。组件 ID、页面、区域和简短文字作为模型上下文。模型仍可修改关联文件。
- 代码标签支持查看文件、选择历史版本做文件对比、恢复单个文件。恢复会创建新版本，且不会自动重新验收。源码 ZIP 包含源码与可独立打开的 preview.html。已有 HTML 快照可继续浏览、下载和恢复。
